## Limits of this measurement

- Grounding checks scan SQL with patterns, not a parser: `FROM`/`JOIN` targets and `alias.column` references are checked, unqualified columns are not.
- Since v0.45.4 the artifacts come from AutoDE's deterministic build: `autode_primitive_candidates` for each source in `plan.yaml`'s `buildSources`, every valid step accepted, compiled by the engine. It measures what the engine gives a pipeline engineer to start from; the agent's own choices (and its custom SQL) are measured with host-agent runs (PA3c).
- The plan steps in `plan.yaml` are used only to measure context delivery per step.
- Ablation: run with `--sut ledger` (the global dump, same ledger) or `--sut baseline` to compare against context packs on identical inputs.
- Chat extraction (C4b) needs the LLM. Offline, a stand-in returns each turn's scripted facts as the extractor's JSON (outcomes such as status, trust, supersession and conflicts withheld); validation, subject resolution, dedup and correction linking are the engine's own work, and the engineer's Inbox confirmation is simulated per turn. Extraction quality itself is measured by hand (manual-verification Part 18).
- Plan steps and questions each get their own context pack. The fixed reference plan is executed with the hub's context provider and an ArtifactWriter, exactly as the extension wires them.
